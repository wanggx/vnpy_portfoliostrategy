## 1. 背景：现状全部是滞后判定

| 环节 | 当前条件 | 性质 |
|---|---|---|
| 买入触发 | 窗口内涨幅 ≥ `surge_pct`(3%)，**或** 相对昨收涨幅 ≥ 3% | 已经涨完才买（追高） |
| 买入过滤 | 当前大盘/行业评级（同步快照）：**大盘中性以下一票否决**（任何标的都不买入），其余按档看行业 | 看水平，不看趋势 |
| 止损 | 相对开仓价 ≤ −2%（10:00 后）/ −4%（10:00 前） | 已亏到位才砍 |
| 清仓止盈 | 收益 ≥ `clear_profit_pct`(20%) | 已涨到位才走 |
| 减半止盈 | 收益 ≥ `half_profit_pct`(10%) | 同上 |
| 回撤止盈 | `max_profit − 当前 ≥ 10%` | 浮盈已还回去 10% 才走 |
| 保底线 | `max_profit ≥ 10%/5%/3%` → 保 5%/2%/0% | 同上，全部回看历史峰值 |
| 情绪离场 | 收益 < 3% 且行业评级**已**转为中性以下 | 转变完成后才走 |
| 布林上轨止盈 | 现价 ≥ 当日日线布林上轨（前复权 MA + 2×σ）且收益 ≥ 5% | 动态目标位（兜底，5% ≤ 收益 < 10% 时生效） |

两个直接代价：

1. **买入**：+3% 才进，成本天然偏高；T+1 又锁住当天不能卖，等于把风险全押在"这波会不会延续"上，而这个问题当前完全没有被判断。
2. **卖出**：5 档全是"幅度"阈值，缺"速度/结构"维度。急跌 3 分钟跌 2% 与阴跌 2 小时跌 2% 触发动作完全相同；行业分数**连续下行**但尚未跌破"中性以下"时毫无反应。

此外，越"硬"的常数越难适配不同标的：3% 对日振幅 2% 的大盘股是暴涨，对日振幅 8% 的题材股只是起步。

**本文的预设**：预判**不追求"准"，只追求期望值变好** —— 所有条件都是概率优势，不是确定性（见 §3.3）。

## 2. 目标与非目标

**目标**

- 在不破坏现有硬兜底的前提下，为买入/卖出各增加"提前量"：买入从"追高"改为"确认"；卖出增加一档早于硬止损的减仓。
- 尽可能复用**已有数据**（tick 自带字段、情绪快照 breadth、`stock_near_ma` 的 score）。
- **性能不退化**：所有新增计算必须满足 §3.2 的预算与规约（≈3 秒快照、每 tick < 200 µs），并把现存的两处每-tick 开销（峰值落盘、窗口最小值扫描）一并压平。

**非目标**

- 不做自动调参、不做机器学习模型。
- 不改动止损/清仓/减半止盈/冷却期/委托超时告警这些兜底逻辑（它们必须保持"一定会触发"）。
- 除盘口/资金流外不引入新的数据源（本次设计全部落在现有数据内）。

## 3. 全局前提（≈3 秒快照 / 性能预算 / 数据核实）

> 本章前提适用于**后面所有方案**：任何指标的定义、阈值单位、实现方式都必须先满足这里。

### 3.1 前提一：行情是 ≈3 秒快照（不是逐笔）

- A 股 Level-1 快照约 **3 秒**一笔，`on_tick` 的实际频率是"每标的每 3 秒一次"（不是逐笔成交）。
- 因此 `tick.last_volume` 是**这 3 秒内的累计成交量**，**不是"单笔量"**。任何"单笔 / 逐笔 / 大单"口径的判断都不成立，判断活跃度只能用 ≥ 3 秒的桶。
- **窗口指标的单位是"样本数"而非"秒"**：`surge_window=300` 秒 ≈ 100 个样本；`MIN_VOL_SAMPLES=20` ≈ 60 秒。
- **分辨率上限**：任何速度快于 3 秒的指标都是噪声，所以斜率一律用**分钟级**尺度（涨幅/分钟）表达。
- 快照可能稀疏（无成交不推送）：实际样本数会少于"时长/3s"，样本数类阈值要按最坏情况设（例如 `MIN_VOL_SAMPLES=20` 实际覆盖时长可能 > 60 秒）。

### 3.2 前提二：计算性能预算与实现规约

**规模假设**：当日池 ≤ 100 只 + 持仓若干 → 约 **33~40 次 `on_tick` / 秒**；按 200 只留余量 = 67 次/秒。

**预算**（单次 tick 的纯计算，不含下单/日志）：

- 目标：**< 200 µs / tick**（200 只时 ≈ 1.3% 单核）
- 上限：**< 1 ms / tick**，超过必须查原因

**实现规约（所有方案都要遵守）**：

1. **每 tick 只做 O(1)**：`deque.append` / `popleft`（摊销 O(1)）、字段读取、算术比较；禁止每 tick 全窗口扫描、排序、list 切片、pandas/numpy 小数组。
2. **O(N) 只允许"惰性 + 每 tick 至多一次"**：仅在"候选接近门槛"时把窗口跑一遍（N ≈ 100），且 **②③ 等多项指标共用同一遍循环**，不要每项各扫一遍。
3. **慢周期指标必须缓存**：情绪趋势 / RS 趋势依赖 **30 秒一次**的快照 → 在快照 `datetime` 变化时算一次并缓存，每 tick 只读缓存（O(1)）。
4. **I/O、日志、通知必须限流**：`sync_data()` 落盘、`write_log`、`send_wecom`、`put_event()` 只在**状态变化 / 命中**时调用；"被拒原因"用**计数器聚合**，禁止每 tick 打印。
5. **字符串拼接只在命中时**：`reason` 文案不要每 tick 构造（现有代码已是命中才拼，保持）。
6. **新增状态要能释放**：per-symbol 状态在退订时清理（沿用 `SellAggregator.remove` 的模式），避免字典无限增长。

**现有代码中已存在的每-tick 开销（本次要一并处理）**：

| 位置 | 现状 | 影响 | 建议 |
|---|---|---|---|
| `signals/sell_signals.py:333` | `_update_max_profit` 每创出新高就 `_sync_tracking_state()` → `save_json` 全量落盘 | 上涨过程中几乎**每 3 秒写一次盘**（同步 I/O 在事件线程上） | 改**脏标记 + 节流**：内存先更新峰值，落盘按"每 N 秒 / 或峰值变化 ≥ x%"节流（或只在停止时落盘） |
| `signals/buy_signals.py:96` | `min(price for _, price in self.window)` 每 tick 全窗口扫描 | N ≈ 100，200 只时约 1.3 万次比较/秒（尚可但没必要） | 改**单调队列**（滑动最小值摊销 O(1)），或与 ②③ 合并到同一遍循环 |

**性能自检（建议一起加）**：在 `on_tick` 首尾用 `time.perf_counter()` 累计，输出"平均 / 最大耗时"到启动日志与 UI 变量，超预算即告警 —— 上线后能第一时间发现退化。

### 3.3 前提三：所有条件都是概率优势，不是确定性

> 这一条决定了"怎么判断一个条件有没有用"和"条件该怎么组合"，①②③… 全部按这个口径设计。

没有任何条件能百分百：每个条件只是把**胜率**或**赔率**往有利方向推一点。所以设计目标不是"过滤掉所有假突破"（那会同时杀掉真突破），而是**让期望值变大**。

#### 核心公式

| 指标 | 公式 | 说明 |
|---|---|---|
| 胜率 | `p = 盈利笔数 / 总笔数` | 只看频率 |
| 事前赔率 | `r = (目标价 − 入场价) / (入场价 − 止损价)` | 下单前算，用于赔率过滤（候选 ⑨） |
| **事后赔率** | `r = 盈利笔的平均盈亏 / |亏损笔的平均盈亏|` | **评价策略必须用这个**（止损/止盈很少刚好打到） |
| 期望值 | `E = p × W̄ − (1 − p) × L̄` | 唯一该拿来比好坏的指标 |
| 盈亏平衡胜率 | `p_min = 1 / (1 + r)` | r = 2 时只要胜率 > 33.3% 就不亏 |
| R 单位表达 | `E(R) = p × r − (1 − p)`，止损幅度 = 1R | 便于跨标的 / 跨参数比较 |

示例（100 笔，止损 2% = 1R）：盈利 40 笔均 +3%(1.5R)、亏损 60 笔均 −1.2%(0.6R)
→ `p = 0.40`、事后赔率 `r = 2.5`、`E = 0.4×1.5R − 0.6×0.6R = 0.24R/笔`、`p_min = 28.6%` → 正期望。
注意这里必须用**事后**赔率 2.5，而不是事前假设的 3.0。

#### 条件分三类，但用同一把尺子（E）比较

| 类型 | 改变什么 | 本方案成员 | 只看它会得出的错误结论 |
|---|---|---|---|
| **胜率型** | 提高 `p`，代价是机会数变少 | ② 量能、③ 质量、⑤ 情绪趋势、⑥ RS（候选 ⑧⑪） | "胜率高了就是好" ❌ |
| **赔率型** | 提高 `r`（入场点位 / 目标空间） | ④ VWAP 买点（候选 ⑨） | 买点下移可能让 `p` 略降，但 `E` 变好 |
| **处置型** | 压低亏损分布 `L̄`、砍掉尾部 | 止损分档、④ 卖出第 6 档、冷却期 | 与入场无关，不能用胜率评价 |

**判断某条件有没有用**：比较"满足该条件组"与"不满足组"的 **E**，不是比较 `p`。
反例：某条件把 `p` 从 40% 提到 45%、但事后赔率从 2.5 掉到 1.6 → `E` 从 `0.24R` 降到 `0.17R`，**是负贡献**。

#### 条件串联会让机会数指数衰减（本方案最大的风险）

②③⑤⑥⑦ 目前都是"叠加 / 否决" = 乘法。示例（通过率为**假设值**，非实测）：

```
每天池内拉升命中 20 次
 × ② 0.7 × ③ 0.6 × ⑤ 0.8 × ⑥ 0.7 × ⑦ 0.6 ≈ 2.8 次/天
 再叠候选 ⑧⑨⑩⑪（各 0.8）→ ×0.8^4 ≈ 1.1 次/天
```

≈ 1~3 笔/天 ≈ **20~60 笔/月** —— 样本量不足以统计判断"参数改好还是改坏"。因此：

- 条件组合优先用 **"打分 + 最少满足 N 项"** 或 **"必须项（少而硬）+ 加分项（多而软）"**，不要全部取与；
- 每个硬否决条件都要回答："它误杀真突破的代价，值不值得？"（③ 已用打分处理；**②⑤⑥ 目前仍是硬否决，是最该重新权衷的地方**）；
- 仓位可以是"打分结果 × 赔率过滤"的组合，而不是"每一关都过才买"。

#### 对验证与纪律的影响（并见 §8）

- 观察期按**笔数**验收（≥ 100 笔），不按"3~5 个交易日"；
- **单笔结果不能作结论**（一笔亏不代表条件坏）；
- 一次只改一项，参数给区间 / 分位而非点值；
- 优先加**能同时改善赔率**的条件（如 ④ 买点下移、候选 ⑨），而不是继续加"只提高胜率"的过滤器；
- 候选 ⑳（tick 归档 + 离线标定）的真正价值是**解决样本量**，不是提高精度。

### 3.4 Tick 字段与单位

`vnpy_xt/xt_gateway.py::_push_tick` 是**原样透传** QMT 字段：

- `tick.volume = d["volume"]`（累计成交量）、`tick.turnover = d["amount"]`（累计成交额）
- `tick.last_volume = max(tick.volume − 上一次 tick.volume, 0)`（网关自己算的增量）
- A 股 `ContractData.size = VolumeMultiple`（股票为 1）

**单位已确认（2026-09-23，🟢 Q1 结案）：`volume` 为手、`amount` 为元**

证据一：**项目自带的 QMT API 文档直接定义**

- `xtquant_big_convert/docs/BIGQMT_INNER_PYTHON_API_REFERENCE.md:346-347`：
  `| volume | int | 成交总量（手） |`、`| pvolume | int | 原始成交总量（未经股手转换）【不推荐使用】 |`
- `xtquant_big_convert/docs/RPC_API_REFERENCE.md:353`：
  "`pvolume` 是**股**、和流通股本同单位，`['volume']` 是**手**，用它会小 100 倍"
  （举例：600519.SH `3222611 股 / 1250081601 股 = 0.258%`，用 `32226 手` 算出来是 0.00258%）
- `xtquant_big_convert/docs/MiniQMT_2_BigQMT-Skill/QMT内置Python策略手册.md:1140`：`pvolume:成交量（精确到股）`

证据二：**实测反向验证**（本机 `.vntrader/database.db`，QMT 数据源写入的个股分钟/日线）

- `turnover / volume / close ≈ 100.00`；**算术精确验证**：`300779.SZSE 2026-07-03 13:33`，
  `volume=69, amount=408963, close=59.27` → `69 手 = 6,900 股 × 59.27 = 408,963 元`，误差 **0.00**。
- **量级交叉验证**：`000001.SZSE` 日线 `2026-07-06`，`volume=1,061,049`
  → 按手读 = 1.06 亿股、成交额 11.04 亿元（均价 10.404 元，合理）；
  若按股读则成交额只有 1,114 万元，对平安银行明显不合理。

证据三：**仓库内代码旁例**

- `vnpy_xt` 对 `volume` / `amount` 是**原样透传**（`xt_gateway.py::_push_tick`），全包搜不到 `pvolume`，也没任何 `* 100` / `/ 100` 转换 → 网关不给策略做单位归一。
- `vnpy_ctastrategy/strategies/bottom_friction_strategy.py:270` 已经这么算分时均价：
  `tick.turnover / (tick.volume * shares_per_lot)`，其 `shares_per_lot = 100`。

**结论**：`VOLUME_UNIT_FACTOR = 100`，即

```
vwap = tick.turnover / (tick.volume * 100)      # 累计成交额(元) / 累计成交量(手) / 100 股每手
```

**关于碎股（修正）**：文档里 `volume` 的类型是 **int（手）**，即已经做过"股手转换"；而按 `RPC_API_REFERENCE.md` 的示例（600519.SH：`pvolume=3222611 股 → volume=32226 手`，而 `3222611/100 = 32226.11`）可知该转换是**截断/取整**，不足一手的零碎股数会丢失。要股级原始精度只能用 `pvolume`。而 `vnpy_xt::_push_tick` **没有映射 `pvolume`**，所以策略层拿不到股级精度（将来若需要，要在网关补字段）。

对本设计的影响：

- 4.4 的 VWAP 用 `volume`（手）×100 → 精度完全够（均价只到分）。
- 4.2 的**量能确认用量比/段比，比值本身与单位无关**（手/股都一样），受不到影响。
- `tick.last_volume` 是两次 `volume`（手）相减 → **也是手**。

> 仍建议保留一次启动自检打印（`turnover / last_price / volume` 应为 100），防止以后更换数据源时单位静默变化。

可用的 tick 字段（当前策略**只用到了 `last_price`**）：`open_price / high_price / low_price / pre_close / limit_up / limit_down / volume / turnover / last_volume / bid_price_1..5 / bid_volume_1..5 / ask_price_1..5 / ask_volume_1..5`。

### 3.5 情绪快照

- 刷新间隔默认 **30 秒**（`marketsentiment.refresh_interval`），**90 秒**无更新即 `stale`（`marketsentiment.stale_after`）。
- 快照带 `datetime`，**必须按它去重入队**（否则每个 tick 都入队，序列里全是重复值）。
- `MarketSentimentSnapshot`：`score / level / breadth / indices / sectors / sector_score / stale`。
- `MarketBreadth`（大盘与**每个行业**都有）：`universe_size / valid_count / advancing / declining / unchanged / limit_up / limit_down / advance_ratio / decline_ratio / net_advance_ratio / average_change_percent / median_change_percent`。
- `SentimentLevel`：`EXTREME_BEARISH / BEARISH / NEUTRAL / BULLISH / EXTREME_BULLISH / UNAVAILABLE`。

结论：**行业基准、RS、情绪趋势都不需要新数据源**。

### 3.6 现有可复用的运行时状态

- 策略持有 `entry_prices` / `max_profit_pct`（T+1 JSON 持久化）、`entered`、`cooldown_dates`。
- `universe_data` 已存 `stock_near_ma` 全行（含 `score / near_days / near_values / high52w`）但**当前未参与任何决策**。

## 4. 方案清单

### 4.1 阈值动态化（`surge_pct` → 自身波动归一）

**动机**：固定 3% 对不同波动率标的含义完全不同。

**买入条件**

| 关系 | 条件 | 动作 |
|---|---|---|
| **替换**现有 3% 门槛 | `窗口涨幅 >= eff_surge` **或** `昨收涨幅 >= eff_surge` | 产生买入意向（后续仍要过 ②③⑤⑥） |
| 降级 | `pre_close <= 0` 或 `high <= low`（振幅不可用） | 回落固定 `surge_pct` |

**卖出条件**：无（本项只作用于买入门槛）

**定义**（只用 tick 自带字段，不引入日线依赖）

```
vol_ref   = max( (high_price - low_price) / pre_close,  MIN_VOL_REF )
eff_surge = clamp( SURGE_VOL_K * vol_ref,  MIN_SURGE_PCT,  MAX_SURGE_PCT )
命中条件：gain >= eff_surge        # 窗口基准仍是窗口内最低价，不变
```

| 参数 | 建议值 | 说明 |
|---|---|---|
| `use_dynamic_surge` | `True` | 开关；关掉即退回固定 `surge_pct`，便于 A/B |
| `SURGE_VOL_K` | `0.5` | 需涨到"当日振幅"的一半 |
| `MIN_SURGE_PCT` | `0.015` | 低波动票也要 1.5% 才算异动 |
| `MAX_SURGE_PCT` | `0.05` | 高波动票别超过 5%，否则买不到 |
| `MIN_VOL_REF` | `0.02` | **关键**：开盘前几分钟 `high == low`，振幅基准为 0 会让门槛趋零 |

**降级**：`pre_close <= 0` 或 `high <= low` → 回落固定 `surge_pct`（宽进，不阻断）。

**落点**：`signals/buy_signals.py::WindowSurgeSubSignal.on_tick`；把 `eff_surge` 写进 `reason` 便于复盘。

**复杂度**：每 tick O(1)（读 `high/low/pre_close` 三个字段 + 几次算术），无新增状态。

**待确认**
- Q2：是否需要引入"昨日 ATR/振幅"作为基准（更稳，但要新增日线数据依赖）？
- Q3：`k = 0.5` 是否合适，还是应该按"当日振幅 × k + 固定底"？

### 4.2 量能确认

**动机**：过滤无量假突破。比率是**单位无关**的，不受 Q1 影响。

**买入条件**

| 关系 | 条件 | 动作 |
|---|---|---|
| **叠加**（新增门槛） | `V_up / V_down >= VOL_RATIO_MIN(1.5)` | 通过，继续后续过滤 |
| 叠加（特例） | `V_down == 0` 且 `Σ last_volume > 0`（窗口内一路不回落） | 通过（不除零） |
| 叠加（**否决**） | 窗口内 `Σ last_volume == 0`（无成交 / 停牌） | **不买** |
| 降级 | 窗口样本数 < `MIN_VOL_SAMPLES(20)` | 不阻断（放行 + 记日志） |

**卖出条件**：无（卖出侧的"缩量反弹无力"归到 4.4 第 6 档的可选加强项）

**口径（唯一）：段量比** —— 只看**这一波拉升内部**：涨的时候成交多、跌的时候成交少，就是真买盘在推；不跟别的时间段比。

> 设计取舍：曾评估的"窗口速率比"（窗口内成交速率 ÷ 开盘至窗口起点的速率）**已放弃** —— 跨时间段比较本身不等价，且开盘放量会把基准抬高、早盘容易误杀（见变更记录 v0.7）。

**计算步骤**（窗口样本为 `(t_i, p_i, last_volume_i)`）：

1. 逐个样本判方向（**死区用相对幅度，跨标的可比**）：`change_i = (p_i − p_{i-1}) / p_{i-1}`
   → `change_i > +VOL_SEG_MIN_PCT` 算上行、`change_i < −VOL_SEG_MIN_PCT` 算下行、否则算**中性**（不计入任一段）。
   实际生效的死区取 `max(VOL_SEG_MIN_PCT, pricetick / p_{i-1})` —— 避免低价股的百分比死区小于 1 个报价单位而形同虚设；
2. 把该样本的成交量 `last_volume_i` 累加到对应段：`V_up` / `V_down`
   （`last_volume_i` 是"上一次快照→本次快照"的成交量，按**本快照的价格方向**归类即可）；
3. `vol_ratio = V_up / V_down`，要求 `>= VOL_RATIO_MIN`。

含义：`V_up` 大 = 每一分上涨都有成交量配合（量价齐升）；`V_down` 大 = 涨是缩量、跌是放量（拉高出货 / 假突破）。

示例（窗口内 5 个快照，`VOL_RATIO_MIN = 1.5`）：

| 样本 | 价格 | last_volume | 方向 | V_up | V_down |
|---|---|---|---|---|---|
| 1 | 10.00 | 300 | 首个样本（不计） | 0 | 0 |
| 2 | 10.05 | 800 | 上行 | 800 | 0 |
| 3 | 10.02 | 900 | 下行 | 800 | 900 |
| 4 | 10.08 | 1200 | 上行 | 2000 | 900 |
| 5 | 10.12 | 700 | 上行 | 2700 | 900 |

→ `vol_ratio = 2700 / 900 = 3.0 ≥ 1.5` ⇒ 量价配合，**通过**。

边界与降级：

- `V_down == 0`（窗口内一路不回落）→ 视为极强，**直接通过**（不能除零）；
- 窗口内 `Σ last_volume == 0`（无成交 / 停牌）→ **不买**（本身就是坏信号）；
- 窗口样本数 < `MIN_VOL_SAMPLES` → **不阻断**，只记日志（宽进）。

3 秒快照里单笔 `last_volume` 常为 0，**按段聚合**比逐笔判定稳（0 也参与累加，不丢信息）。

注意：`last_volume` 是"上一次快照 → 本次快照"的增量，所以分段是按**样本**而非按时间切的。若某标的快照稀疏（盘中瞬间无成交不推送），缺失区间的量会归到下一个快照的方向上，属可接受的近似（A 股 3 秒快照下样本基本均匀）。

**参数**

| 参数 | 建议值 | 说明 |
|---|---|---|
| `VOL_RATIO_MIN` | `1.5` | 最低段量比（`V_up / V_down`） |
| `MIN_VOL_SAMPLES` | `20` | 窗口最少样本数（3 秒快照 ≈ 1 分钟） |
| `VOL_SEG_MIN_PCT` | `0.0005`（5bp，待 Q4 标定） | 死区：相邻样本价格变化比小于它就算"中性"（滤 1 个 pricetick 级别的抖动）；死区下限用 `pricetick / price` 兜底 |

**落点**：`WindowSurgeSubSignal` 的窗口样本由 `(datetime, price)` 扩为 `(datetime, price, last_volume, cum_volume)`；仅在 `gain` 接近门槛时才计算，避免每 tick 全量开销。

**复杂度**：窗口维护 O(1)（`append` / `popleft` 摊销）；段量比是**惰性 O(N)**（N ≈ 100，且与 4.3 共用同一遍循环，每 tick 至多一次）。若要进一步压，可在弹出时按样本记录的贡献从 `V_up`/`V_down` 扣减，改成增量 O(1)（**默认不做**，先保证正确）。

**待确认**
- Q4：`VOL_SEG_MIN_PCT` 取多少（5bp 只是起步，需观察期分位标定）；以及中性样本的量**丢弃**还是计入平盘段 `V_flat`（丢弃会让分母变小、比值虚高）。

### 4.3 拉升质量（斜率 / 路径回撤 / 脉冲）

**动机**：区分"台阶式上攻"与"单根脉冲一冲就回落"。

**买入条件**

| 关系 | 条件 | 动作 |
|---|---|---|
| **叠加**（新增门槛 + 定量） | `quality` = 三项打分（回撤 / 脉冲 / 量能），按**失败项数**决定 | 失败 0 项 → 满仓；失败 1 项 → 半仓；失败 >= 2 项 → 不买（待 Q6） |
| 各项通过条件 | ① 路径回撤 `<= 1%`；② 脉冲占比 `< 0.8`；③ 4.2 段量比通过 | 细节、算法、示例见下 |

**输入**：与 4.2 **共用同一份窗口样本** `(t_i, p_i, last_volume_i)`（`WindowSurgeSubSignal.window`，3 秒快照下 `surge_window=300s` ≈ 100 个样本），**不新增数据结构**；三项指标与 4.2 的段量比在**同一遍循环**里算完（§3.2 规约 2）。

**为什么是这三项**（各对应一种假突破形态，互相独立，所以用"打分"而不是"取与"）：

| 假突破形态 | 对应指标 |
|---|---|
| 一冲就回落（冲高后砸下来） | 路径回撤 |
| 单根直线脉冲（一口价拉上去、不可持续） | 脉冲占比 |
| 上涨无量（价格上去了成交没跟上） | 4.2 段量比 |

**指标定义与算法**

**① 路径回撤（窗口内）**

```
peak = p_0; dd = 0
for (t, p) in window:              # 跳过 p <= 0 的样本
    peak = max(peak, p)
    dd   = max(dd, (peak - p) / peak)
通过条件：dd <= MAX_SURGE_DRAWDOWN(1%)
```

- `peak` 从**窗口首个样本**起累计（窗口语义本身就是"从低点起算的这一波"，与现有 `WindowSurgeSubSignal` 一致）。
- 注意它与卖出侧"相对 `max_profit` 的回撤"**是两回事**，互不影响。

**② 脉冲占比**

```
lookback_price = 窗口内最接近 (now - PULSE_WINDOW) 的那个样本价
pulse_share    = (p_now - lookback_price) / (p_now - p_low)      # p_low = 窗口最低价
通过条件：pulse_share < PULSE_SHARE(0.8)
```

- 含义：**整波涨幅里有多大比例是"最近 60 秒一口气冲出来的"**，占比越高越像脉冲。
- 前提：`PULSE_WINDOW(60s) <= MIN_SURGE_SPAN(180s)` —— 否则窗口跨度不足 60 秒时占比恒为 1，会被误判为脉冲；跨度不足时该项**跳过**（不否决）。
- 分母 `p_now - p_low == 0`（平盘）→ 该项跳过。

**③ 斜率（仅记录，暂不作门槛）**

```
x_i = (t_i - t_0) 秒；y_i = ln(p_i)
slope = Σ(x_i - x̄)(y_i - ȳ) / Σ(x_i - x̄)^2          # 每秒对数收益率
slope_pct_per_min = exp(slope * 60) - 1              # 转成"每分钟涨跌 %"
```

- 只写进日志 / 消息，用于复盘"这波是缓涨还是陡拉"。
- 暂不作门槛的原因：**陡拉本身常常就是脉冲**，"斜率越大越好"是错的；若要参与判定，更合理的是设**下限**（太慢说明不是有效异动）→ Q18。
- 退化实现：不想做最小二乘时可用首尾法 `(p_now/p_low)^(1/span_sec) - 1`，但价格离散（pricetick）时噪声更大，**建议直接用最小二乘**（一遍循环 O(N)）。

**打分与仓位**

| 项 | 通过条件 | 得分 |
|---|---|---|
| 路径回撤 | `dd <= MAX_SURGE_DRAWDOWN(1%)` | 1 |
| 脉冲占比 | `pulse_share < PULSE_SHARE(0.8)` | 1 |
| 量能（4.2） | `V_up / V_down >= VOL_RATIO_MIN(1.5)` | 1 |

```
可判项数 = 3 - 跳过项数            # 数据不足的项：不计分、也不否决
quality  = 通过项数
失败项数 = 可判项数 - quality
失败 0 项   → 满仓 fixed_size
失败 1 项   → 半仓 ceil(fixed_size / 2 / 100) * 100
失败 >= 2 项 → 不买（待 Q6 确认是否改半仓）
```

**设计取舍**：脉冲/回撤不合格时是**降级为半仓**而不是直接拒绝 —— 单根脉冲也可能是真突破（封板），直接拒绝会错过；减半能在保留机会的同时控成本。只有"多项同时不合格"才拒绝。

**两个示例**（窗口 300 秒，窗口低点 10.00、现价 10.30，即窗口涨幅 3.0%）

| 情形 | 路径回撤 | 脉冲占比 | 段量比 | quality | 结果 |
|---|---|---|---|---|---|
| A 台阶式上攻：低点 10.00 → 10.32（t≈180s）→ 回落到 10.30；最近 60 秒 10.21 → 10.30 | `(10.32−10.30)/10.32 = 0.19%` ✓ | `(10.30−10.21)/(10.30−10.00) = 0.30` ✓ | 2.1 ✓ | 3/3 | **满仓** |
| B 单根脉冲：前 240 秒在 10.00~10.05 磨，最近 60 秒 10.05 → 10.30，中途冲高 10.44 后回落 | `(10.44−10.30)/10.44 = 1.34%` ✗ | `(10.30−10.06)/(10.30−10.00) = 0.80` ✗ | 0.9 ✗ | 0/3 | **不买** |

**边界与降级**

- 窗口样本数 < `MIN_QUALITY_SAMPLES(20)`（3 秒快照 ≈ 1 分钟）→ **不判质量**，放行 + 记日志（与 4.2 的样本不足处理一致，宽进）；
- 样本 `p <= 0` → 跳过该样本，不参与任何项；
- 可判项数为 0（数据全缺）→ 放行 + 记日志；
- 全部为 O(N) 惰性计算，无新增状态、无 I/O。

**落点**：`WindowSurgeSubSignal`；建议抽出内部方法 `_surge_quality(window) -> (metrics, quality)`，与 4.2 的段量比**共用同一遍循环**；`dd / pulse_share / slope_pct_per_min / quality` 一起写进 `reason` 与观察期日志。

**复杂度**：惰性 O(N) 一遍循环（与 4.2 共用），每 tick 至多一次；**三项指标在同一遍循环里算完，不要分三趟**。

**注意**：`_buy_result` 现在硬写 `s.fixed_size`，需支持传入量；引擎 `check_t1_order` 要求买入量为 **100 的整数倍**。

**卖出条件**：无（本项只决定"买不买、买多少"）

- Q7：半仓是否只在"失败 1 项"时使用，还是引入连续仓位（按通过比例线性）？

### 4.4 分时结构 VWAP

**定义**

```
vwap = tick.turnover / (tick.volume * VOLUME_UNIT_FACTOR)      # VOLUME_UNIT_FACTOR = 100（已实测确认）
```

**复杂度**：每 tick O(1)（两次除法 + 比较）。"最近 `VWAP_SELL_SECONDS` 秒未收回 vwap"只需记**一个时间戳**（最后一次 `price >= vwap` 的快照时间），不需要序列。

**买入条件 / 卖出条件**（两条独立支路，细节见 4.4.1 / 4.4.2）

| 侧 | 关系 | 条件 | 动作 |
|---|---|---|---|
| 买入 | **替换**"直接追高" | 拉升命中 → 回踩到 `vwap × (1+VWAP_PULLBACK_DELTA)` → **重新站上 `vwap × (1+VWAP_RECLAIM_DELTA)`** | 买入（买点≈均价线上方 0.5%） |
| 买入 | **明确不兜底** | 一直不回落、等不到标准回踩 | **不买**（漏掉就漏掉，风险交后续硬止损） |
| 买入 | **否决** | `price <= vwap × (1 − VWAP_PULLBACK_FAIL)`（跌穿 VWAP 过多，不是回踩是反转） | 本轮作废 |
| 卖出 | **新增第 6 档** | `price < vwap` 且 `VWAP_SELL_SECONDS(180s)` 内未收回 且 `profit_pct < half_profit_pct` 且 `profit_pct > -当前止损档(2%/4%)` | **减半**（不清仓） |

#### 4.4.1 买入：把"追高"改成"右侧确认"

做成独立子信号 `VwapPullbackSubSignal`，插在拉升 OR 之后、行业过滤之前（对窗口/昨收两条支路都生效），带开关 `use_vwap_pullback`。

**只考虑标准回踩形态（拉升 → 回踩到当日均价线附近、不深破 → 重新站上均价线），且只用价格条件、不设任何时间/样本时限**：不做"等 N 秒未回踩就按现价买"的兜底 —— 等不到标准回踩就**放弃这波**（漏掉就漏掉），买入的风险敞口交给后面的硬止损把关。

**买点为什么定在"重新站上均价线"而不是"再破前高"**：前高就是这波拉升的顶点，等破前高等于买在最高价（比回踩低点贵 1% 以上）；在 T+1 下当天没有卖出机会，**买得越高越危险**。改成"回踩不深破 + 重新站上均价线"后，买点落在**当日成本线附近**，既有确认（买盘把价格推回均价线上方），点位又比前高低得多。

状态机（每标的独立，触发后持续维护到"买入"或"作废"）：

| 当前状态 | 条件 | 动作 / 新状态 |
|---|---|---|
| WAIT（拉升已命中，等回踩） | 任意 tick | 记录回踩前高点 `trigger = max(trigger, price)`（**仅日志/复盘**，不参与判定） |
| WAIT | `price <= vwap × (1 + VWAP_PULLBACK_DELTA)` | 回踩成立 → PULLBACK |
| WAIT | `price <= vwap × (1 − VWAP_PULLBACK_FAIL)` | 没形成回踩就跌穿 VWAP → **本轮作废 + 当日封禁** |
| PULLBACK | `price >= vwap × (1 + VWAP_RECLAIM_DELTA)` | **买入**（重新站上均价线） |
| PULLBACK | `price <= vwap × (1 − VWAP_PULLBACK_FAIL)` | 回踩过深（是反转不是回踩）→ **本轮作废 + 当日封禁** |
| WAIT | 一直不回落 | 停在 WAIT，**不买**（漏掉接受） |

- **作废即封当天**：一旦作废，写入**当日作废标记**（`vt_symbol → YYYYMMDD`，仅运行时、不持久化），该标的**当日不再进入买入判定** —— 实现上加在买入前置检查里，与 `entered`、亏损冷却期并列；日切自然失效（按日期比较，旧记录在盘前刷新时清掉，避免无限增长）。
- **确认基准固定为当日 VWAP**（分时均价线），不引入"开盘价 / 前高"等替代基准。
- 两条线之间留**缓冲带**：回踩到位线 `+δ(0.2%)`、买入线 `+δ'(0.5%)`，中间 0.3% 的距离避免价格贴着均价线来回抽搐时反复进出状态；
- 作废线 `−VWAP_PULLBACK_FAIL(1%)` 与回踩到位线拉开距离，避免把"正常回踩到均价线附近"与"真的反转走弱"混为一谈；
- `trigger`（回踩前高点）只写进日志，用于观察期**对比两种买点（站上均价线 vs 破前高）的价差**，不参与任何判定。

| 参数 | 建议值 | 说明 |
|---|---|---|
| `VWAP_PULLBACK_DELTA` | `0.002` | 回踩到位线：跌到 `vwap × (1+0.2%)` 以内即算回踩成立 |
| `VWAP_RECLAIM_DELTA` | `0.005` | 买入线：重新站上 `vwap × (1+0.5%)` 才买（与上路留 0.3% 缓冲带） |
| `VWAP_PULLBACK_FAIL` | `0.01` | 作废线：跌穿 VWAP 超过该幅度 → 回踩失败，本轮作废 |

**代价**：会漏掉两类机会 —— ① 不给回踩、一路上冲的强势票；② 回踩后直接跌破均价线（走弱）的票。这是**有意为之**：宁可漏掉，也不在未确认的位置追高；被漏掉的收益靠前置条件（如 4.7 池内优选）提高命中率来补，而不是靠放宽买点。

#### 4.4.2 卖出：新增第 6 档「跌破分时均价 → 减半」

- 条件：`price < vwap` **且** 最近 `VWAP_SELL_SECONDS` 秒内未回到 vwap 上方 **且** `profit_pct < half_profit_pct`（**必须**，否则会把 10% 止盈仓提前砍掉）**且** `profit_pct > -stop_pct`（还没到硬止损）；
- 可选加强：反弹段量能 < 下跌段量能 × `VWAP_SELL_RECLAIM_SHRINK`（"缩量反弹无力"）；
- 动作：**减半**，不清仓，保留硬止损兜底；
- 优先级：放在 `PriceSellSubSignal._decide` **最后**（第 6 档），不抢占止损/清仓/减半止盈。

| 参数 | 建议值 |
|---|---|
| `VWAP_SELL_SECONDS` | `180` 秒 |
| `VWAP_SELL_RECLAIM_SHRINK` | `0.5` |

### 4.5 情绪看趋势（不只看水平）

**采样**：以快照 `datetime` 去重入队，保留最近 `SENTIMENT_TREND_SECONDS` 秒。

**缓存内容**

- 大盘：`(datetime, score, net_advance_ratio, limit_down)`
- 行业（策略的 `industry_name`）：`(datetime, score, breadth.average_change_percent, breadth.decline_ratio)`

**判据（二选一，建议先用判据二）**

- 判据一｜斜率：`(score_now − score_N分钟前) / 分钟数 <= SENTIMENT_SLOPE_MIN`
- **判据二｜单调下行（推荐）**：连续 `>= MIN_TREND_SAMPLES` 个采样点分数下降且累计降幅 `>= SENTIMENT_TREND_DROP`

| 参数 | 建议值 |
|---|---|
| `SENTIMENT_TREND_SECONDS` | `600`（≈20 个采样点） |
| `MIN_TREND_SAMPLES` | `3` |
| `SENTIMENT_TREND_DROP` | `3.0` 分（累计降幅） |
| `SENTIMENT_SLOPE_MIN` | `-2.0` 分/分钟（用判据一时才需要） |

**买入条件**

| 关系 | 条件 | 动作 |
|---|---|---|
| **叠加**（新增否决） | 大盘或行业情绪判定"快速转弱"（判据见上） | **不买**（即使评级仍在中性以上） |
| 降级 | 采样数 < `MIN_TREND_SAMPLES(3)` 或快照 `stale` | 不触发（不阻断买入） |

**卖出条件**

| 关系 | 条件 | 动作 |
|---|---|---|
| **扩展现有情绪离场** | （现有：行业评级 ≤ 中性 **或** 新增：行业情绪趋势转弱）且 `profit_pct < TIER_BREAKEVEN_PCT(3%)` | 清仓 |
| 降级 | 采样数不足或快照 `stale` | 不触发（不提前卖） |

**降级**：采样数不足或 `snapshot.stale` → **不触发**（既不阻断买入也不提前卖），与现有"缺数据不放宽"一致。

**落点**：`signals/sentiment_signals.py` 新增 `SentimentTrendTracker`（大盘 + 行业序列 + 两个判据），买卖两侧共用；策略持有一个实例注入子信号。

**复杂度**：每 tick O(1)（只读缓存结果）；序列入队与判据计算**仅在快照 `datetime` 变化时执行**（≈ 30 秒一次，O(20)）。**不得每 tick 采样**（否则序列里全是重复值，且白耗 CPU）。

### 4.6 个股相对强弱（RS）

**定义**（基准用现成数据，零新增）

```
个股日内涨幅 = (price - pre_close) / pre_close
rs_sector    = 个股日内涨幅 - breadth.average_change_percent      # 建议行业用 median 防个别涨停拉偏均值
rs_market    = 个股日内涨幅 - snapshot.breadth.average_change_percent
```

**买入条件**

| 关系 | 条件 | 动作 |
|---|---|---|
| **叠加**（新增否决） | `rs_sector < RS_BUY_MIN(0)`（弱于板块） | 不买（避免买同板块跟风票） |
| 降级 | 行业未映射 / 快照不可用 | 不启用（不阻断） |

**卖出条件**

| 关系 | 条件 | 动作 |
|---|---|---|
| **收紧**现有止损档 | `rs_sector < 0`（弱于板块） | 取消宽档（4%），全天用常规档 2% |
| 提前减半 | `rs_sector` 在 `RS_DROP_WINDOW(30s)` 内下降 `>= RS_DROP_MIN(1%)` | 走 4.4 第 6 档减半 |
| 降级 | 行业未映射 / 快照不可用 | 不放宽止损、也不提前减半（保持现有行为） |

| 参数 | 建议值 |
|---|---|
| `RS_BUY_MIN` | `0.0` |
| `RS_DROP_WINDOW` / `RS_DROP_MIN` | `30` 秒 / `0.01` |

**降级**：行业未映射或快照不可用 → 不启用（不放宽、也不阻断）。

**复杂度**：每 tick O(1)（读快照 breadth + 一次减法）；RS 趋势缓存同 4.5（30 秒一次）。

## 5. 目标链路与优先级

### 5.1 买入链（目标形态）

```
SurgeBuyOrSignal(窗口拉升 | 昨收涨幅)          # 现有，① 动态阈值 ② 量能 ③ 质量 增强
        ↓
VwapPullbackSubSignal（可选开关）               # 新增 ④：右侧确认 / 超时兜底 / 破位放弃
        ↓
SectorBuySubSignal                              # 现有行业过滤 + 新增 ⑤ 情绪趋势否决 + ⑥ RS 门槛
        ↓
订单数量 = fixed_size × quality 分档            # 新增 ③/⑦：满仓 / 半仓
```

### 5.2 卖出链（目标形态）

卖出总信号本身是优先级短路（`SellAggregator` → `SellSubSignal`），内部两层：

```
1  行业情绪离场（SectorSellSubSignal）        ← 现有；新增 ⑤ 趋势转弱也可触发
2  价格卖出（PriceSellSubSignal._decide，内部 5 档顺序）
   2.1 分档止损（宽档/常规档）             ← 现有；⑥ 新增"弱于板块则取消宽档"
   2.2 清仓止盈（clear_profit_pct）
   2.3 减半止盈（half_profit_pct）
   2.4 回撤止盈（MAX_DRAWDOWN_PCT）
   2.5 保底收益线
   2.6 VWAP 破位减半（新增第 6 档）        ← 仅 profit < half_profit_pct 且未到硬止损时生效
```

**不变**：止损/清仓/减半止盈的硬阈值、`cooldown_dates`、委托超时告警 —— 全部保留为兜底。

### 5.3 新增条件汇总（一处审阅）

**买入侧（按链上顺序叠加）**

| 顺序 | 归属 | 关系 | 条件 | 动作 |
|---|---|---|---|---|
| 1 | ⑦ | 前置筛选 | `score >= SCORE_MIN`（或板块内前 N） | 不达标不建信号 |
| 2 | ① | **替换**门槛 | `窗口/昨收涨幅 >= eff_surge`（按自身振幅动态） | 产生买入意向 |
| 3 | ② | 叠加 | `V_up / V_down >= 1.5`；窗口总量为 0 → 拒绝 | 通过 / 不买 |
| 4 | ③ | 叠加 + 定量 | 打分（回撤 / 脉冲 / 量能）：**失败 0 项满仓、1 项半仓、>=2 项不买** | 决定是否买、买多少 |
| 5 | ④ | **替换**买点 | 拉升 → 回踩到 `vwap×(1+0.2%)` → 重新站上 `vwap×(1+0.5%)` 买入；跌穿 `vwap×(1−1%)` → 作废且**当日不再起一轮**；**无时间兜底** | 买入 / 作废（当日封禁） |
| 6 | ⑤ | 叠加否决 | 大盘或行业情绪快速转弱 | 不买 |
| 7 | ⑥ | 叠加否决 | `rs_sector < 0`（弱于板块） | 不买 |

**卖出侧（按优先级插入现有链）**

| 位置 | 归属 | 关系 | 条件 | 动作 |
|---|---|---|---|---|
| 第 1 档（现有情绪离场） | ⑤ | 扩展触发 | 行业评级 ≤ 中性 **或** 情绪趋势转弱，且 `profit < 3%` | 清仓 |
| 第 2 档（现有止损） | ⑥ | 收紧 | `rs_sector < 0` | 取消宽档（4%→2%） |
| 第 6 档（新增） | ④ | 新增 | 跌破 vwap 未收回 且 `profit < half_profit_pct` 且未到硬止损 | 减半 |
| 第 6 档加强项 | ②/⑥ | 新增 | 缩量反弹无力（量能比对） / RS 30 秒内骤降 ≥1% | 触发减半 |

**性能前置（与功能解耦，可先单独上线并观察）**：① `on_tick` 耗时埋点；② `_update_max_profit` 落盘节流；③ 窗口最小值扫描合并进同一遍循环。对应 §11 的 step 0。

## 8. 验证方案

1. **观察期埋点（先不参与判定）**：每个新条件都算出结果并写进日志，例如
   `快速拉升候选 000001.SZSE 窗口3.4% eff↑2.6% 量比0.8 回撤1.4% rs-0.6 vwap上方 质量1/3`。
   同时记录每笔的**入场价、出场价（或当前价）、出场原因、触发过哪些条件**，用于算 `p` / `r` / `E`（§3.3）。
   验收按**笔数**（≥ 100 笔）而不是按天；**单笔结果不作结论**。
2. **一次只开一个开关**：每个条件独立开关，开启后单独跑几天，否则出问题无法归因。
3. **回测可行性确认**：需确认 `backtesting.py` 能否回放"情绪快照 + 动态订阅池 + tick 逐笔"；若不行就用候选 ⑳（tick 归档 + 离线标定）兜底 —— 它的价值是**解决样本量**（一个月就能积累足够笔数），而不是提高精度。
4. **联动复核**：这些改动会让成交次数下降、持仓时间变长，需一并复核 `COOLDOWN_DAYS`、`fixed_size`、`half_profit_pct`。
5. **性能验收（每项改动都要看）**：`on_tick` 平均耗时目标 **< 200 µs**（200 只标的 ≈ 1.3% 单核）、上限 1 ms；同时观察 `_sync_tracking_state`（落盘）次数/分钟、日志条数/分钟。超预算就回退该项。

## 9. 风险与权衡

| 风险 | 说明 | 缓解 |
|---|---|---|
| 参数过拟合 / 样本量不足 | 每加一项就多一组参数，而机会数会被条件串联指数衰减（§3.3）→ 只剩 20~60 笔/月，不足以判断改好还是改坏 | 条件用"打分 + 最少满足 N 项"而非全与；参数给"区间/分位"；一次只开一个开关；按笔数（≥100）验收；用候选 ⑳ 做离线标定 |
| 漏掉强势票 | 4.4.1 的 VWAP 回踩确认**不设时间兜底**，等不到标准回踩就不买 → 会漏掉"不给回踩机会"的强势票（如直接封板） | **有意为之**：宁可漏掉也不在未确认的位置追高；靠前置条件（4.7 池内优选等）提高命中率来补 |
| 卖得过早 | 第 6 档（VWAP 破位减半）可能在震荡中反复减半 | 限定 `profit < half_profit_pct`（+Q8 的"当天只减一次"标记） |
| 数据依赖 | 情绪 30 秒采样、VWAP 单位 | 严格降级：缺数据不阻断买入、不允许放宽止损 |
| 可解释性下降 | "硬阈值"变成多条件组合，出问题更难定位 | 每条 `reason` 带全部维度；拒绝也写日志+计数 |
| 性能退化 | ≈3 秒快照 + 池内上百只 → 每 tick 预算紧；新指标若每次全窗口扫会有可见开销 | 见 3.2 规约：每 tick O(1)、O(N) 惰性共享、慢指标缓存、日志/落盘限流；上线前先装耗时埋点 |

## 11. 推进顺序（建议）

0. **性能前置**（与功能解耦，可最先做）：`on_tick` 耗时埋点 + `_update_max_profit` 落盘节流 + 窗口最小值扫描改增量 —— 先把"每 tick 的开销底座"压平，后面加指标才有预算。
1. **④ VWAP**（买入右侧确认 + 卖出第 6 档）——直击"追高"与"只会硬止损"，零新数据；单位已确认（Q1 结案）。
2. **① 动态阈值 + ⑥ RS** —— 解决"3% 对不同票含义不同""买进同板块弱票"。
3. **② 量能 + ③ 质量** —— 过滤假突破，但参数最多、最需要观察期。
4. **⑤ 情绪趋势 + ⑦ 池内优选** —— 上限最高，放最后，且需先确认采样稳定性。
