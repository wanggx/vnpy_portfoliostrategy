## 1. 背景与目标

策略表现与大盘强相关，但**现在所有"大盘"判据都只看"水平"（当前分/当前评级），没有一维"趋势/形态"**：

| 位置 | 现在的判据 | 性质 |
| --- | --- | --- |
| 买入准入 `SectorBuySignal` | 大盘**评级**中性以下（偏弱/极弱）→ 一票否决 | 看水平 |
| 买入准入（快照不可用） | 行业需中性以上（严格档） | 看水平 + 降级收紧 |
| 行业离场 `SectorSellSignal` | 标的**所属行业**评级中性以下 | 看水平 |
| 止损档 `PriceSellSubSignal._sentiment_ok` | 大盘快照可用 + 行业可用 → 才允许 10:00 前放宽 | 看可用性 |
| `MarketRiskOffSignal` | ⚠️ **占位实现**（`RISKOFF_SCORE_THRESHOLD=20`，"待业务规则确定"），且 `is_risk_off()` **无任何调用点** | 未接线 |

问题：`score` 从 70 掉到 58 的过程中，评级还是"中性"，买入照常放行；等跌破 45 变成"偏弱"才拦截，**已经晚了一到两个交易日**。而"分数正在往下走"这件事，数据其实一直都在（见 §3）。

**目标**：新增一条**比评级更早**的大盘转弱判据，命中即**停开新仓**（买侧提前避险）。

**非目标（本轮不做）**：
- 不做"少买"（趋势转弱时只开半仓）——原因见 §6.2，需要先改掉"是否已减半"的推断方式；
- 不改卖侧（离场规则、止损档保持现状）；
- 不引入指数技术线（`vnpy_technicallines`）、不引入形态相似度匹配（`vnpy_patternsearch`）——本轮只用情绪序列趋势，零新依赖。

## 2. 决策定案

| # | 决策项 | 定案 | 理由 / 代价 |
| --- | --- | --- | --- |
| 1 | 方向 | **提前避险**（少买、早停买），只做**停开新仓** | 比"等评级跌破"更早避开下行段；代价是可能错过 V 型反转的头两天 |
| 2 | 判据来源 | **情绪序列趋势**（`get_daily` / `get_intraday`） | 现成的两条序列，零新依赖、零新数据通道 |
| 3 | 日内判据 | 四条都实现，**日内档默认关闭**（`TREND_INTRADAY_ENABLED=False`） | 日线三条先跑，看命中频率与效果；日内档留开关随时开 |
| 4 | 生效方式 | **直接生效拦截**（不做观测模式） | 命中即停开新仓；回滚手段见 §6.4 |
| 5 | 阈值 | 用 §4.4 的建议默认值（写死常量，不暴露为参数） | 与现有"阈值不暴露"惯例一致；跑一段再按日志调 |

## 3. 数据基础（已核对 `vnpy_marketsentiment` 源码）

| 接口 | 实际行为 | 本次用途 |
| --- | --- | --- |
| `engine.get_latest()` | 当前快照：`score`(0~100)、`level`、`breadth`、`indices`、`sectors`、`stale`、`available` | 取"今天的分"与可用性 |
| `engine.get_daily()` | **全部已存交易日**，日期升序，`DailyPoint(score/level/advancing/declining/...)`；**含当日**（每次采样都用"当天最后一根分钟"更新今天那条） | 趋势基线：日线累计下滑、连续走弱、退潮 |
| `engine.get_intraday()` | 当天分钟点升序，`IntradayPoint(score/level/advancing/declining/limit_up/limit_down/net_advance_ratio/sector_score)` | 日内急速转弱（默认关） |

三个必须注意的点：

1. **当日的分是滚动值**。`get_daily()` 最后一根是"今天到目前为止"，早盘波动极大。
   → 趋势基线**必须排除当日**（`trading_day < today`），只拿"已收盘日"算斜率/退潮；今天的状态用 `snapshot.score`。
2. **日线序列只累积 App 运行过的日子**。`daily.json` 存在 `~/.vntrader/marketsentiment/`，重启不丢，但**新装/清空后从零开始**。
   → 样本不足时相关判据**不参与**（不会一开机就全停买，行为退化为现状）。
3. **快照可用性有门槛**：`available = level != 不可用 且 breadth.valid_count > 0 且 not stale`（`stale_after` 默认 90 秒，采样 30 秒一次）。
   → 不可用时本判定**不触发**（见 §4.3）。

## 4. 判定设计

### 4.1 四条判据（并联 OR，任一命中即"转弱"）

`N` 表示"已收盘日"序列（不含今天，升序），`s` 表示今天的 `snapshot.score`。

| # | 判据 | 公式 | 默认阈值 | 设计意图 |
| --- | --- | --- | --- | --- |
| 1 | **日线趋势下滑**（主） | `s < 60` 且 `N[-5].score − s >= 5` | 5 日下滑 ≥ 5 分 | "已经不强 + 正在往下走"，比评级跌破 45 早 1~2 天 |
| 2 | **连续走弱** | `s < 60` 且 含今天在内连续下降天数 ≥ 2 | `TREND_FALL_DAYS=2` | 短周期方向确认 |
| 3 | **情绪退潮** | `max(N[-20:].score) − s >= 20` | 回看 20 日、回撤 ≥ 20 分 | 从强势区大幅回落（哪怕评级还在偏强） |
| 4 | **日内急速转弱**（默认关） | 近 10 分钟 `max(分时 score) − s >= 8` | `ENABLED=False` / 10 分钟 / 8 分 | 当天先停买（速度判据，**不设 `s < 60` 门槛**） |

前三条都要求 `s < 60`（中性及以下）：**大盘很强时的短期回落不停买**，只在"已经不强且正在变弱"时才避。判据 4 是速度而非水平，故不设该门槛（这是一处可议点，见 §9）。

### 4.2 判定顺序与短路

```
1 → 2 → 3 → 4，首个命中即返回 weakening=True，并把命中判据写进 reason
（reason 例：日线趋势下滑 6.2 分（5 日） / 情绪连续走弱 3 日 / 情绪退潮 24.0 分 / 日内急速转弱 9.1 分）
```

未命中时返回 `weakening=False`，但仍带回可观测量（`slope_drop` / `fall_days` / `retreat` / `closed_days`），供排查看"离阈值还有多远"。

### 4.3 降级原则（缺数据不额外收紧）

| 情况 | 行为 |
| --- | --- |
| 情绪 App 未加载（`get_sentiment_engine` 返回 None） | 不转弱（返回 False），写一条降级日志（沿用现有一次性告警） |
| 快照不可用（过期 / 有效标的不足 / 评级不可用） | 不转弱：此时**评级档已按严格档处理**（行业需中性以上），趋势档不再叠加收紧 |
| 已收盘日样本不足（< 对应判据需要的根数） | 该条判据不参与；全部样本不足 → 不转弱 |

"缺数据不额外收紧"与卖侧的"降级不触发"一致，也与"不会因为 App 刚启动就把所有买入停掉"的目标一致。

### 4.4 参数（常量，写死在判定器类上）

| 常量 | 默认 | 说明 |
| --- | --- | --- |
| `TREND_SCORE_BELOW` | `60.0` | 只有分数已在中性及以下才判趋势转弱 |
| `TREND_SLOPE_DAYS` / `TREND_SLOPE_DROP` | `5` / `5.0` | 判据 1：几个已收盘日前的收盘分作基准 / 累计下滑多少分 |
| `TREND_FALL_DAYS` | `2` | 判据 2：连续走弱天数（含今天） |
| `TREND_RETREAT_DAYS` / `TREND_RETREAT_POINTS` | `20` / `20.0` | 判据 3：回看多少个已收盘日的高点 / 回撤多少分 |
| `TREND_INTRADAY_ENABLED` | `False` | 判据 4 开关 |
| `TREND_INTRADAY_MINUTES` / `TREND_INTRADAY_DROP` | `10` / `8.0` | 判据 4：只看近多少分钟 / 从高点回落多少分 |

## 5. 接入点

### 5.1 落点：`SectorBuySignal.is_buyable`（不新增链节点）

```
① 大盘评级中性以下？          → 一票否决（现状，reason="大盘评级中性以下"）
② 大盘趋势转弱？(新增)        → 一票否决（reason=趋势判据文案）
③ 行业按大盘分档准入          → （现状不变）
```

**为什么放在判定器里而不是新增链节点**：复用现有"大盘拦截"机制——不查行业、按日去重只记一次日志/企微、**不写 `entered`**（大盘转好后标的再起拉升仍可买入）。若做成链上新节点，这套去重与文案逻辑要再写一份。
顺序上**评级优先于趋势**：两条件是 OR，先后不影响结果，但评级判定更便宜，且保留现有日志语义（评级已偏弱时仍显示"评级"原因）。

判定器无状态、纯读内存序列（`daily.json` 与分时都在内存里），且只在"前序有 BUY 意向"时才被调用（`SectorBuySubSignal.on_tick` 在 `prev.type != BUY` 时直接返回），**不在每 tick 热路径上**。

### 5.2 结果字段与消息文案

`SectorBuyResult` 新增 `blocked_reason: str = ""`（放最后、带默认值，既有位置参数构造不受影响）：

- 评级拦截 → `"大盘评级中性以下"`
- 趋势拦截 → `MarketTrendResult.reason`（如 `"日线趋势下滑 6.2 分（5 日）"`）

`SectorBuySubSignal._log_market_block` 用它替换硬编码的尾句，文案变为：

```
大盘情绪拦截 600000.SSE(浦发银行) 买入价格 10.20 大盘 评级 中性 得分 52.3 行业 - 评级 - 得分 0.0，日线趋势下滑 6.2 分（5 日），不买入
```

## 6. 边界与风险

| # | 风险 | 说明与处置 |
| --- | --- | --- |
| 6.1 | **机会数衰减** | 四条判据是 OR，比单一阈值更容易触发停买。判据 1 加了 `s < 60` 门槛来收敛；命中频率要**看日志复盘**（每条拦截都带判据与数值）。若一周内命中天数过多，优先调大 `TREND_SLOPE_DROP`（5 → 8）或收紧 `TREND_SCORE_BELOW`（60 → 55） |
| 6.2 | **不能做"少买"** | `PriceSellSubSignal` 用 `is_halved = 0 < sellable < fixed_size` 推断"是否已减半"；若开仓量不是 `fixed_size`，减半止盈档会被**误判为已减半而永久跳过**。要做"趋势转弱只开半仓"，必须先给"已减半"加显式持久化标记，属独立改动 |
| 6.3 | **可能错过 V 型反转** | 判据 1/2 会在"中性 + 下行"时停买，而急跌后的 V 型反转恰恰发生在这种环境。这是"提前避险"的固有代价；`entered` 不写，所以大盘一恢复（判据不再命中）**当天就能继续买**，不会锁死 |
| 6.4 | **阈值未经验证** | 回滚/调参手段（按侵入性排序）：① 调大阈值常量；② 判据 4 关掉（已是默认）；③ 若需整体关闭，把 `TREND_SCORE_BELOW` 设为 0（三条水平判据即永不命中）或临时把 `is_weakening` 的调用注释掉 |
| 6.5 | 停买期与"持仓不动" | 本判据**只影响开新仓**，已有持仓的止损/离场/布林上轨止盈完全不变（卖侧不在本轮范围） |

## 9. 未决项

1. **判据 4 是否也要 `s < 60` 门槛**：现在是"速度判据不看水平"（大盘很强时 10 分钟跌 8 分也停买）。若觉得过严，加同一门槛即可。
2. **是否要"降档"而非"全停"**：例如"趋势转弱但评级仍中性以上 → 只停买一日"或"只减半"。后者受 §6.2 制约。
3. **是否需要卖侧联动**：趋势转弱时把 10:00 前的止损宽档收掉（`_sentiment_ok` 加趋势条件），让已有持仓在转弱初期更早离场——这属于卖侧，需单独确认是否本轮做。
